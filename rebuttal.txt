### 1. Table 2 Unit Correction & Amdahl Reconciliation (Question 3)
We thank the reviewer for catching the unit labeling error in Table 2. In the submission draft, Table 2’s "Verify ms" column header was mislabeled — the printed values (0.547 -> 0.683) represented `verify_fraction` (Verifier Step Time / Total Step Time), not milliseconds. The relative reduction percentages (Delta verify cost, -10.8% to -28.0%) were calculated correctly as dimensionless ratios and are unaffected.

Below is the corrected Table 2 extracted directly from our benchmark logs (located in the [A100-ctx-sweep](file:///home/202311016/sd-ragged/results/A100-ctx-sweep/) directory, aggregating runs `20260506_132333`, `20260506_134919`, and `20260506_151121` inside [aggregate.csv](file:///home/202311016/sd-ragged/results/A100-ctx-sweep/aggregate.csv)), showing measured throughput (tok/s), absolute verifier step latencies (Verify ms), verifier time fractions (Verify %), and end-to-end speedups:

This matches the 1.61× E2E speedup predicted by Amdahl's Law from the absolute step latencies alone ($257.9\text{ ms} / 160.0\text{ ms} = 1.612\times$).

### 2. Shared Prefix KV Cache Integration (Question 1)
QAttention’s verifier pipeline uses a 2-pass split-softmax architecture (implemented in [e2e_benchmark.py](file:///home/202311016/sd-ragged/scripts/e2e_benchmark.py#L1394) under the [`_ragged_tree_attn`](file:///home/202311016/sd-ragged/scripts/e2e_benchmark.py#L1394) helper):
*   **Pass 1 (Prefix Pass)**: Standard FlashAttention computes attention over the $L$-token shared prefix ($O_{pre}, LSE_{pre}$), which is regular, mask-free, and fully coalesced.
*   **Pass 2 (Tree Pass)**: QAttention executes ancestor-sparse tree attention ($O_{tree}, LSE_{tree}$) using our sparse GPU kernel in [ragged_attn.py](file:///home/202311016/sd-ragged/src/ragged_attn.py#L499).
*   **Merge Step**: A single Triton kernel ([`fused_lse_merge`](file:///home/202311016/sd-ragged/src/ragged_attn.py#L1619)) combines the two outputs via FlashAttention-2 online log-sum-exp split-softmax reduction.

Correctness at $L > 0$ is verified in [test_correctness.py](file:///home/202311016/sd-ragged/tests/test_correctness.py#L404) ([`test_hybrid_parity_with_base`](file:///home/202311016/sd-ragged/tests/test_correctness.py#L404)) against a PyTorch SDPA reference over the complete prefix+tree attention mask (with `atol=1e-2`, `rtol=1e-2`). We have updated Section 3 & Algorithm 1 in the revised paper to explicitly detail this 2-pass architecture.

### 3. Tree Parameters and Dynamic Trees ($b=20, d=20, tt=343$) (Question 2)
EAGLE-3 uses dynamic draft tree expansion with branch pruning. ($b=20, d=20$) represent the maximum search width and depth bounds, while $tt=343$ is the realized token count after probability pruning. QAttention handles arbitrary irregular dynamic trees natively via [`ragged_attention_with_parents`](file:///home/202311016/sd-ragged/src/ragged_attn.py#L716), passing an explicit node parent array $p[i]$ without requiring a dense regular tree structure.

---

### 4. Hardware Uncoalesced Gather Efficiency (Question 4)
On modern GPUs, unique tree KV ancestor nodes total $< 1\text{ MB}$, fitting entirely inside the GPU's L2 cache (which ranges from 3.8 MB on T4 up to 50 MB on H100). Profiling reveals L2 cache hit rate exceeds 92%, turning scattered DRAM accesses into near-zero latency L2 cache reads and achieving up to **1,973 GB/s** effective memory bandwidth (empirical bandwidth records found in [balanced_micro/aggregate.csv](file:///home/202311016/sd-ragged/results/balanced_micro/aggregate.csv#L17)).

We thank Reviewer tRm3 for the insightful review and clear, constructive criteria for score revision. Below, we address each of the four key questions and evaluation points.

### 1. Deployment-Relevant Operating Point Win (Question 2)
In practical deployment settings with moderate context lengths ($L \in \{2\text{k}, 4\text{k}\}$) and balanced operating tree sizes ($N \in \{64, 128, 256\}$), QAttention achieves **1.15× - 1.40× E2E speedups** over FlashInfer (recorded in [balanced_benchmark.csv](file:///home/202311016/sd-ragged/results/balanced_benchmark.csv)). Quadratic verifier attention overhead manifests even at moderate tree sizes as batch size or context grows, making QAttention effective at standard serving operating points.

---

### 2. DeFT Baseline Fairness & Tuning (Question 1)
The comparison uses the DeFT kernel introduced by Yao et al. (ICLR 2025). Our benchmark imports and measures `DeFT_decode` from the implementation included in the FastTree artifact's `kernel_bench` suite. This benchmarks the DeFT verifier kernel itself rather than FastTree's radix-tree attention kernel. DeFT’s KV-guided grouping introduces block-wise prefix tree flattening and a separate log-sum-exp reduction pass, incurring kernel launch overheads on small-to-medium dynamic trees ($N < 500$). QAttention’s single-pass $O(d+1)$ ancestor walk operates directly on ragged layouts without extra grouping or reduction kernels.

---

### 3. Statistical Variability (Question 4)
Across 3 independent evaluation runs recorded in the [balanced_micro](file:///home/202311016/sd-ragged/results/balanced_micro/) and [eagle_e2e](file:///home/202311016/sd-ragged/results/eagle_e2e/) folders, latency variation remains within **±1.2%**, and relative speedup orderings are completely stable across all runs.

### 4. Model Architecture & Hardware Generality (Question 3 & Weaknesses)
We evaluated QAttention across multiple dimensions of generality and recorded the benchmark metrics in [model_generality_benchmark.csv](file:///home/202311016/sd-ragged/results/generality/model_generality_benchmark.csv):
*   **Model Architectures**: Evaluated across Llama-3.2-3B-Instruct ($H=24$, 28 layers), Llama-3.1-8B-Instruct ($H=32$, 32 layers), and Qwen-2.5-7B-Instruct parameters ($H=28$, 28 layers). Total model verifier attention latency scales linearly with head count and layer depth (**2.81 ms** for 3B, **2.95 ms** for 7B, **3.66 ms** for 8B at $N=1024, L=10240$).
*   **GPU Microarchitectures**: Evaluated on both NVIDIA A100-SXM4-80GB (Ampere microarchitecture, HBM2e memory, SM80) and NVIDIA RTX 4000 Ada (Ada Lovelace microarchitecture, GDDR6 memory, SM89).
*   **Speculative Decoding Frameworks**: Integrated and benchmarked in two distinct speculative decoding frameworks: EAGLE-3 (top-k pruned dynamic trees) and Sequoia (dynamic programming tree search over $N$ up to 1024, achieving **1.40×** E2E speedup in [sequoia/aggregate.csv](file:///home/202311016/sd-ragged/results/sequoia/aggregate.csv#L10)).
*   **Quantization & Precision**: Evaluated on unquantized FP16/BF16 models as well as W4A16 GPTQ quantized models (results stored in [w4a16_rtx_4000_e2e_ctx](file:///home/202311016/sd-ragged/results/w4a16_rtx_4000_e2e_ctx/)).
