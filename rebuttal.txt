### Question 2: Shared Prefix KV Cache Integration
> *"It is unclear how QAttention incorporates the shared prefix KV cache... How is the shared prefix KV cache incorporated into QAttention? Algorithm 1 appears to attend only to tree ancestors; is prefix attention computed separately?"*

We appreciate the reviewer raising this important point of clarification. We would like to clarify that QAttention does not attend only to tree nodes.

Verification is implemented as a **two-pass split-softmax pipeline**:

* The shared prefix is processed using standard FlashAttention over the prefix KV cache.
* The speculative tree is processed using the ancestor-sparse QAttention kernel.
* The two partial attention results are merged using FlashAttention-2's online log-sum-exp formulation.

This preserves exact attention semantics while allowing only the tree portion of the computation to exploit ancestor sparsity.

Correctness is verified against PyTorch SDPA over the complete prefix-plus-tree attention mask, demonstrating numerical equivalence for both prefix and tree attention.

### Question 3: Dynamic Trees & Parameter Notation ($b=20, d=20, tt=343$)
> *"The definitions of branching factor, depth, and tree size are inconsistent—for example, b=d=20 is reported with only 343 nodes—and the regular-tree parent formula does not directly support dynamic trees."*

We thank the reviewer for raising this question regarding tree notation and parameter definitions. We agree that the distinction between theoretical search bounds and realized tree size requires explicit clarification.

The quantities **b** and **d** denote the maximum branching factor and maximum search depth, while **tt** denotes the realized number of speculative tokens after probability pruning.

Consequently, **b = 20**, **d = 20**, and **tt = 343** are not inconsistent. They describe the search limits and the realized tree after pruning rather than a complete regular tree.

QAttention operates directly on an explicit parent array and therefore supports arbitrary ragged trees without assuming a regular topology.

### Question 4: Hardware Efficiency & Memory Access Uncoalescing
> *"How efficient are the ancestor-gather accesses at the hardware level? Will it decrease the memory loading efficiency due to uncoalesced and duplicate KV loads?"*

We appreciate the reviewer highlighting this key memory efficiency concern. We agree that scattered memory accesses can degrade bandwidth if working sets overflow cache limits. However, for the evaluated configurations, the unique ancestor KV working set is less than **1 MB**, allowing it to reside almost entirely in GPU L2 cache. Profiling shows L2 hit rates above **92%**, substantially reducing DRAM traffic despite the irregular access pattern.

Consequently, the reduction in logical memory accesses translates into measured bandwidth and latency improvements rather than being offset by uncoalesced memory accesses.

### Question 2: Significance & Acceptance-Rate Plateauing
> *"Significance undercut by own analysis: headline 7.75x/16.99x at b=d=28, but Sec 4.4 shows acceptance plateaus by N≈50... Kernel makes bad points less bad; optimal point (1.0x) unchanged."*

We appreciate the reviewer's insightful analysis regarding tree size optimization and acceptance-rate plateauing. We agree that today's standard draft models often exhibit declining acceptance rates as depth increases. Our interpretation is that this reflects **two independent bottlenecks** rather than a single limitation.

The first is verifier complexity. Existing verifier kernels scale quadratically with tree size, making larger trees increasingly expensive regardless of acceptance rate. QAttention removes this systems bottleneck by reducing verifier complexity from **O(N²)** to **O(N·d)** while preserving exact attention semantics.

The second is acceptance-rate degradation. As discussed in the paper, current draft models exhibit declining acceptance as tree depth increases, this is fundamentally a modeling problem, and there has been no need for higher acceptance rates because of the quadratic complexity of tree verification. Draft objectives, reward functions, and speculative decoding strategies continue to evolve, and improvements in draft quality can directly improve acceptance.

We therefore view these two bottlenecks as complementary. QAttention does not claim to solve acceptance decay. Rather, it removes the computational barrier that would otherwise prevent future improvements in draft quality from translating into end-to-end inference gains.

Additionally, Reviewer tRm3 notes that acceptance decay often limits optimal tree sizes in standard draft setups. However, acceptance rate behavior varies heavily with the tree construction algorithm. Unlike standard sampling, Sequoia's DP tree optimizer explicitly scales tree size to $N=1024$ because its tree search continues to increase the expected accepted tokens per step. In Sequoia, large trees directly correspond to higher accepted tokens per step. QAttention eliminates the $O(N^2)$ verifier cost, achieving up to 1.41x at N=1024.

More broadly, the algorithm is not specific to speculative decoding. It exploits ancestor-sparse attention, a property shared by a broader class of tree-structured computations. We focus on speculative decoding because it is currently the most consequential deployment setting, but the same execution strategy is applicable wherever attention follows ancestor-defined dependency graphs.

### Question 4: DeFT Baseline Fairness & Tuning
> *"DeFT < FlashInfer everywhere: how was it tuned, and is the comparison on its intended balanced-tree regime fair?"*

We thank the reviewer for raising this important question regarding baseline fairness and tuning. Our comparison evaluates the published **DeFT** verifier kernel (Yao et al., ICLR 2025).

DeFT performs additional grouping and reduction operations before attention. QAttention instead operates directly on the ragged parent representation using a single ancestor walk, eliminating those preprocessing stages while preserving exact outputs.
