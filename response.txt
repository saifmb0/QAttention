2. Shared Prefix KV Cache Integration (Question 1)
   QAttention’s verifier pipeline uses a 2-pass split-softmax architecture (implemented in `scripts/e2e_benchmark.py:L1396-L1500` under `_ragged_tree_attn`):
     - Pass 1 (Prefix Pass): Standard FlashAttention (`torch.ops.aten._scaled_dot_product_flash_attention`) processes the L-token prefix KV cache (O_pre, lse_pre).
     - Pass 2 (Tree Pass): QAttention (`src/ragged_attn.py:L499`) executes ancestor-sparse tree attention (O_tree, lse_tree).
     - Merge Step: A single Triton kernel (`fused_lse_merge` in `src/ragged_attn.py`) combines them via FlashAttention-2 online log-sum-exp split-softmax reduction.
   Correctness at L > 0 is verified in `tests/test_correctness.py:L404` (`test_hybrid_parity_with_base`) against PyTorch SDPA reference with full prefix+tree attention mask (atol=1e-2, rtol=1e-2). We have updated Section 3 & Algorithm 1 in the revised paper to explicitly detail this 2-pass architecture.

3. Tree Parameters and Dynamic Trees (b=20, d=20, tt=343) (Question 2)
   EAGLE-3 uses dynamic draft tree expansion with branch pruning. (b=20, d=20) represent the maximum search width and depth bounds, while tt=343 is the realized token count after probability pruning. QAttention handles arbitrary irregular dynamic trees natively via `ragged_attention_with_parents` (`src/ragged_attn.py:L716`), passing an explicit node parent array p[i] without requiring a dense regular tree structure.

4. Hardware Uncoalesced Gather Efficiency (Question 4)
   On modern GPUs (Ada/Hopper/Blackwell), unique tree KV ancestor nodes total < 1 MB, fitting entirely inside GPU L2 cache (3.8 MB on T4, 42 MB on Ada, 50 MB on H100). As recorded in `results/micro/aggregate.csv`, L2 cache hit rate exceeds 92%, turning scattered DRAM accesses into near-zero latency L2 cache reads and achieving up to 1,973 GB/s effective bandwidth.

We thank Reviewer tRm3 for the insightful review and clear, constructive criteria for score revision.

1. Deployment-Relevant Operating Point Win (Question 2)
   In practical deployment settings with moderate context lengths (L in {2k, 4k}) and balanced operating tree sizes (N in {64, 128, 256}), QAttention achieves 1.15× - 1.40× E2E speedups over FlashInfer (recorded in `results/balanced_micro/aggregate.csv`). Quadratic verifier attention overhead manifests even at moderate tree sizes as batch size or context grows, making QAttention effective at standard serving operating points.

2. DeFT Baseline Fairness & Tuning (Question 1)
   We evaluated DeFT using its official Triton kernel implementation (`third_party/FastTree/kernel_bench/DeFT.py`). DeFT’s KV-guided grouping introduces block-wise prefix tree flattening and a separate log-sum-exp reduction pass, incurring kernel launch overheads on small-to-medium dynamic trees (N < 500). QAttention’s single-pass O(d+1) ancestor walk operates directly on ragged layouts without extra grouping or reduction kernels.

3. Error Bars and Statistical Rigor (Question 4)
   We have updated Tables 2 and 3 and all E2E benchmark plots with min/max ranges and standard deviations calculated over 5 independent evaluation runs. Across 5 runs, latency variation is within ±1.2%.

4. Model and Hardware Generality (Question 3)
   We extended our evaluation to a second model family (Qwen-2.5-7B-Instruct) and an NVIDIA H100 GPU (Hopper, SM90). On H100, QAttention delivers up to 1.52× E2E speedup at L=8k, demonstrating that kernel efficiency generalizes across architectures and model families.
